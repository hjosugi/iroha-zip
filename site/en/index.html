The current official binaries are not Authenticode-signed.

Do not disable SmartScreen warnings. Verify SHA-256 and the GitHub release/workflow attestations. libarchive / bsdtar is not bundled.

If you use v0.5.x or earlier, replace it with the latest v0.6.3, whose one-use channel keeps encrypted-ZIP passwords off argv, the environment, files, and logs.

Separate boundaries.
Inspect before publish.

Untrusted archives never run directly with the user's normal privileges. The backend, working storage, and final destination have distinct boundaries, and no failure silently falls back to a weaker path.

  1. 1. PinMatch the complete bsdtar bundle against its SHA-256 manifest
  2. 2. IsolateEphemeral AppContainer with no capabilities or network access
  3. 3. BoundLimit time, memory, process count, entries, and expanded bytes
  4. 4. RecheckAudit paths, links, ADS, reserved names, identity, and content
  5. 5. PublishAtomically publish only inspected regular files to a new directory
A

Fail closed

If AppContainer setup, hash verification, audit, or cleanup fails, processing stops instead of dropping to normal privileges.

B

Creation is isolated too

The source is audited and copied, and output is re-extracted in a second sandbox. Nothing publishes until the trees match.

C

Provenance is pinned

Validate a backend manifest, source provenance, SPDX SBOM, and license evidence as one exact inventory.

Set up in three steps.

Most users should choose the complete ZIP. The backend is deliberately separate, so import a libarchive build you trust once during initial setup.

01

Download

Get the Windows x64 or ARM64 ZIP that matches your PC from the latest release and extract it into a new folder.

02

Verify

Compare SHA256SUMS.txt with Get-FileHash. Check the Release with gh release verify and gh release verify-asset, then check workflow provenance with gh attestation verify.

03

Configure backend

Open iroha-zip.exe settings, import MSYS2 or a trusted bundle, and run the diagnosis.

Check the digest

Get-FileHash `
  .\iroha-zip-0.6.3-windows-x64.zip `
  -Algorithm SHA256

Configure and diagnose

.\iroha-zip.exe settings
.\iroha-zip.exe doctor

Including legacy Japanese archives.

libarchive automatically detects enabled formats. UTF-8 process mode preserves modern Japanese names; old ZIP and LZH archives that omit encoding metadata can explicitly use CP932. A standalone GZ/BZ2/XZ/Zstandard/.Z stream becomes one safely named file after separate AppContainer preflight and extraction passes.

ExtractZIP / ZIPX, 7z, RAR / RAR5, LHA / LZH, TAR, GZ, BZ2, XZ, Zstandard, .Z, CAB, and more
CreateZIP, 7z, TAR, TAR.GZ
Filename encodingauto, UTF-8, CP932, CP437
Operating systemWindows 10 version 1903 or later; x64/native ARM64 packages, with automated ARM64 evidence on Windows 11 ARM
RuntimeThe architecture-matching Microsoft Visual C++ v14 Redistributable. If VCRUNTIME140.dll is absent, install Microsoft's package rather than using a third-party DLL site
 
iroha-zip.exe extract .\old-japanese.zip --encoding cp932
iroha-zip.exe create seven-zip .\folder .\folder.7z

Explicit rejection,
not silent normalization.

Ambiguous archive structures never become output for convenience. A failed audit publishes nothing and cleans the partial tree.

Important rejection rules

  • .., absolute, drive-prefixed, and UNC paths
  • Symlinks, junctions, reparse points, and hard links
  • NTFS Alternate Data Streams
  • Duplicate members and case/separator aliases
  • Windows reserved names and trailing dots/spaces
  • Configured byte, entry, depth, and path limits
  • Overwriting any existing output

Inspect the evidence

  • Threat model
  • Windows E2E contract
  • Malicious archive corpus
  • Encrypted archive boundary
  • Backend evidence
  • Security policy

Double-click or CLI.

Register file-association candidates from Settings. The CLI exposes preview, selective extraction, creation, and diagnosis through the same policy boundaries.

Extract and preview

iroha-zip.exe preview .\archive.zip
iroha-zip.exe extract .\archive.zip
iroha-zip.exe extract .\encrypted.zip `
  --prompt-password
iroha-zip.exe extract .\archive.zip `
  --select "docs\index.txt"

Create

iroha-zip.exe create zip `
  .\folder .\folder.zip

iroha-zip.exe create tar-gz `
  .\folder .\folder.tar.gz
